# OGBデータ研究所｜サイト導線と代表業務フローの設計案

作成日：2026-11-17。これは**比較・検証用の設計案**。専門分野は未決定で、サイトHTMLにはまだ反映していない。

## A. サイト全体の情報設計

```text
OGBデータ研究所 トップ
├─ 目的から選ぶ（利用者が最初に見る入口）
│  ├─ データをまとめたい → CSV結合・リスト整理
│  ├─ データを照合したい → 注文集計・受注決済照合
│  ├─ 数字を分析したい → CSV分析・グラフ
```

## B. 代表業務フロー1：受注と入金の確認

**想定利用者**：小規模物販事業者（未検証）

1. 注文明細CSVを準備する。**入力**：注文番号・明細金額など。
2. 注文単位に集計する。**処理**：`tools/order-line-aggregate/`。
3. 決済CSVを準備する。**入力**：注文番号・決済金額など。
4. 受注と決済を照合する。**処理**：`tools/order-payment-reconcile/`。
5. **出力**：一致・不一致・片側のみ・重複などを確認する。
6. **判断**：返金・分割決済・手数料など金額定義を確認し、要調査行を切り分ける。

**受入条件案**：既知のサンプルデータで一致・未入金・金額不一致・重複の期待結果を再現できる。照合前後で注文件数・金額が不意に失われない。現実のCSV互換性は別途確認する。

## C. 代表業務フロー2：月次データの統合と分析

1. 月別・店舗別CSVを準備。
2. `tools/csv-merge/` で列の対応と重複を確認して結合。
3. `tools/csv-analyzer/` で欠損・分布・外れ値・グラフを確認。
4. **出力**：元データの統合結果と統計レポート。
5. **判断**：欠損や外れ値の原因を元データに戻って確認する。

**受入条件案**：異なる列順、欠損値、重複行を含むサンプルで、件数と計算結果を検証できる。日付・金額の意味が違う列を自動で同一視しない。

## D. 代表業務フロー3：販売価格と利益の検討

1. 原価・固定費・販売手数料・販売見込み数・目標利益を整理。
2. `tools/pricing-simulator/` で必要販売価格を計算。
3. `tools/index.html#profit` で販売数量別の利益・損益分岐点を確認。
4. **出力**：価格・販売数量の複数シナリオ。
5. **判断**：現実的な販売数量・価格帯との整合を検討。

**受入条件案**：ガイドに掲載した計算例を再現でき、手数料100%や極端な数値を黙って正常値として表示しない。

## E. サイト公開前に必要な横断検証

- [ ] それぞれの業務フローに入力サンプルと期待結果を用意
- [ ] 入口からツール、解説、次の作業まで迷わず移動できる
- [ ] 実際のブラウザで代表ケースと異常ケースを実行
- [ ] 個人情報や取引データの扱いを利用者が理解できる
- [ ] スマートフォン・PCの表示と操作を確認
